# 报告模板 —— 照这个骨架写，不要自由发挥

> 复制下面整块，把 `<>` 填掉。**没有内容的节保留标题并写「无」**，不要删掉 —— 删了读者会以为你忘了。

---

## 写作规则（先读，违反即重写）

**必须**
- **结论先行**：`TL;DR` 一节放最前面，一张表把结论和数字说完。读者只看这一节也应该知道结果。
- **表格优于散文**。三个并列项以上一律用表。
- **每个数字带出处**：命令 + 落盘路径。读者要能自己复现出这个数。
- **每项改动固定三段**：改动清单（`文件:行 → 改前 → 改后 → 依据`）→ 前后对照 → 字段级回归。
- **每轮必须附「来源标注审计」一节**（见下面 §3）：无 `source_label` 的格数 + 按列分布 +
  被来源守卫判坏的格数。并发之后「两趟不一致」已是常态，**没有来源标注就回答不了
  「这一格为什么是这个值」**。命中数下降时必须把「如实标坏」与「漏抽」分开写。
- **原始输出进附录**，正文只放关键 3–5 行。

**禁止**
- ❌ 「已修复」「已优化」—— 必须附命令与输出
- ❌ 「基本一致」「看起来正常」「效果明显」—— 必须附 diff 或数字
- ❌ 把几十行命令输出贴进正文
- ❌ 把结论埋在最后
- ❌ 用「可能」「大概」代替「未验证」（无法验证就写「未验证」）
